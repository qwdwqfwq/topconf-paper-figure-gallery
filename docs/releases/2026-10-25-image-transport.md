# 步骤四图片发送大小修复（2026-10-25）

用户明确解除本次图片发送编码、大小检查、对应测试及发布锁记录的冻结，并授权验证后部署。此修复追加在 19:30 版本之后，不移动该版本标签、不改写历史封存档案。

## 修复范围

火山方舟返回输入图片 16 MiB 超过 10 MiB 上限。此前请求直接发送图片 Data URL，缺少发送前检查。

所有步骤四识图阶段统一检查发送副本：符合上限的图片原样发送；超限先尝试原始像素尺寸的 PNG 无损重编码；仍超限按 JPEG 98%、95%、92%、90% 顺序选择第一个合格结果。JPEG 透明区域合成白底，仅作用于发送副本。原始上传图片、重建坐标、导出所用原图保持不变。

针对 Ark/Doubao，每张图片的解码大小和 Base64 大小均须小于 9,500,000 字节，完整请求 UTF-8 大小须小于 60,000,000 字节。不满足时发送前明确失败，不缩小像素尺寸、不自动重建整图。审计记录编码、质量、大小和重编码尺寸，不记录图片内容。其他服务商保持原发送行为。

生产代码仅修改 `forge/index.html`；发布锁仅更新该文件的哈希。模型、请求参数、提示词、验收标准、一轮修补、导出格式、依赖、缓存、工作流及校验器均保持不变。

- 模拟服务端验证盘点、重建、整图验收、修补及局部检查的全部图片，核对模型参数和引用顺序；验证压缩失败、请求总大小超限与取消均在发送前停止。
- 通过 partial-recovery、tile-fallback、reconstruction-core、source-fidelity 和 reconstruction-browser 回归测试，包含原始尺寸、一轮修补、草稿状态及四种导出。

以上为本地浏览器及模拟 API 验证，未调用用户付费模型，也未声称对用户原图完成真实模型验收。极大或难压缩图片可能仍无法在最低 90% 编码质量下满足上限，此时明确报告而不发送必然超限的请求。
